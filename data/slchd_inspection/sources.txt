Data sources for the food-health-viz MVP and later phases.
Status: implemented | planned | live_later

Ontology targets (semantic/ontology.json): Restaurant, Inspection, ViolationType,
ReviewTheme, SentimentTrend, MarketingSignal, Evidence (sql_fact).

================================================================================
GOVERNMENT / REGULATORY
================================================================================

[implemented] SLC health inspections
  URL:  https://www.saltlakecounty.gov/health/inspection/
  API:  none (ASP.NET postback portal)
  Raw:  https://public.cdpehs.com/UTEnvPbl/VW_EST_PUBLIC/ShowVW_EST_PUBLICTablePage.aspx
  Collector: collectors/slc_inspection_data.py
  Output: data/slc/establishments.csv, inspections.csv, violations.csv
  Ontology: Restaurant, Inspection, ViolationType (via semantic/violation_map)
  Notes: portal exposes ~10 recent inspections per establishment; scrape is resume-safe

[planned] SLCHD violation definitions / inspection rubric (RAG, not a collector CSV)
  Source: SLCHD documentation linked from inspection portal or published PDFs
  Output: semantic/rag/slchd_definitions/ (chunked + embedded)
  Ontology: ViolationType definitions, Evidence (rag_chunk)

================================================================================
RESTAURANT ENTITY / REGISTRY
================================================================================

[planned] Utah business entity search
  URL:  https://businessregistration.utah.gov/
  API:  none (web search; may require scraping or manual lookup for MVP subset)
  Fields to extract:
    - legal entity name, registration / founding date  -> Restaurant.founding_date
    - registered agent / parent entity                   -> RestaurantGroup, sibling_group_id
    - multiple locations under same entity               -> RestaurantGroup.member_restaurant_ids
  Match key: entity name + address fuzzy match to establishments.csv
  Ontology: Restaurant, RestaurantGroup

[planned] Cuisine, menu, allergens
  Sources (TBD per restaurant): OSM tags, delivery menus, restaurant websites
  Ontology: Restaurant.cuisine_type (CuisineType), menu/allergen facts if captured
  Notes: defer until core inspection pipeline is stable

[implemented] Yelp reviews
  API:  Fusion API (free, 500 calls/day, rate-limited; terms apply re: attribution/caching)

  Ontology: ReviewTheme, SentimentTrend

    quota resets. Matched against establishments in
    data/processed/merged_food_inspections.csv.
